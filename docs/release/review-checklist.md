# リリース案チェック（校正＋反証）

対外リリース（告知文・X投稿・画像・説明会資料）を出す前に、**校正**と**反証**の両方を通す。

校正は「書いてあることが正しいか」。  
反証は「正しく書いても、先に誤って読まれないか」。

---

## 1. 校正チェック

- [ ] 事実・日付・金額・手数料が確定文書と一致している
- [ ] 用語が公式表記と揃っている（例: 提携店舗／付与／履行）
- [ ] 法的断定がない（「合法」「必ず安全」等を避ける）
- [ ] 「当社の運用（判断）」として書けている必要箇所がある
- [ ] 未確定事項は「別途案内」「改めてお知らせ」等で切り分けている
- [ ] 発行主体・対象読者（提携店／会員）が明確

---

## 2. 反証チェック（誤読・誤認知の予防）

### 目的

正確でも、**最初に目に入る言葉**や**強い語**だけで、意図と違う物語が広がることがある。  
その誤読を先に想定し、タイトル・画像・短文を直す。

### 手順（短く）

1. **伝えたい核を1文で書く**（社内メモでよい）  
   例: 「保有ウェブコインの利用は続く。終わるのは店舗での新規付与だけ」
2. **見出し／画像の最大文字だけ見て、第三者が言いそうな要約を書く**  
   例: 「ウェブコイン終了」
3. **その要約が核と食い違うなら不合格**  
   - 強い語（終了・廃止・停止・禁止・制限 等）の主語が何か
   - 継続・使える・変わらない、が同じ視線階層にあるか
4. **タイムライン／一覧で3秒見たときの印象**も確認する（本文を読まない前提）

### 観点チェックリスト

- [ ] 見出しだけ読むと、サービス全体の廃止・終了に聞こえないか
- [ ] 「終了／廃止／停止」等の強い語の主語は、変更対象そのものか（例: 付与／申請）
- [ ] 継続メッセージ（使える・続く・変わらない）が、強い語より後段・小さい・弱い位置にないか
- [ ] 画像で、赤字や大見出しが「打ち消したい誤情報」と同程度以上に目立つか
- [ ] すでに流れた誤情報がある場合、それを正面から否定する文があるか
- [ ] 事業者向けと会員向けで、同じ語が別の意味に取れないか

### 不合格時の直し方（例）

| 起きやすい誤読 | 直し方の例 |
|----------------|------------|
| 「ウェブコイン終了」 | タイトルを「利用は継続／付与方法の変更」側に寄せる。「終了」は付与・申請など対象を明示した小見出しへ |
| 「店舗で使えなくなる」 | 冒頭または画像最大見出しで「提携店舗で引き続き使える」を置く |
| 「全部すぐ止まる」 | 移行期間・段階的・日程を、結論の直後に短く置く |

## 3. 今回の教訓（2026-09-07 会員向け画像）

**事実**: 店舗での遊技結果に基づくウェブコインの**付与**を段階的に終了。保有分の利用は継続。

**使った見出し（問題）**:  
「店舗での遊技結果に基づくウェブコインの付与を段階的に**終了**します」

**起きた誤認知**:  
「ウェブコインが終了」——サービス継続の取り組みなのに、タイトルの「終了」が強すぎた。

**学び**:  
本文や赤字で「引き続き利用可」と書いてあっても、**最大見出しの強い語が先に一人歩きする**。反証チェックでは「見出しだけ見た要約」を必ず取る。

---

## 4. 記録

リリースを出したら `docs/release/` に本文・画像・URLを残し、このチェックで直した点があればリリースノートかアーカイブに一行残す。
